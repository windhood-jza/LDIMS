# LDIMS 项目上下文

## 项目定位

LDIMS 是一个文档资料管理系统，包含前端、后端、MCP 服务、共享类型、数据库脚本和部署配置。后续工作不仅包括继续完善项目能力，还包括围绕该项目编写并提交项目比赛文档。

## 当前目标

- 基于现有 LDIMS 项目，整理项目比赛所需材料。
- 完成安徽广播电视台首届 AI 创新应用大赛（“AI 超”）泛技术类参赛材料准备。
- 根据比赛提交表要求，聚焦整理作品/项目核心介绍、业务痛点/创作背景、核心创新点与落地价值、应用场景与效能说明。
- 围绕泛技术类评分维度组织材料：业务痛点解决度、落地部署可行性、工具调用能力、安全性与合规性。
- 准备 3-5 分钟实机操作录屏脚本、提效简述、使用 AI 工具及 AI 生成模块说明、脱敏后核心代码链接或配置文件说明。

## 参赛材料写作重点

- 项目应突出“传统文档管理 + AI 智能增强”的本地化集成平台定位。
- 核心表达方向：从“人找文档”升级为“人与系统对话获取信息、沉淀知识并辅助业务材料产出”，在保障数据本地安全的前提下释放文档知识价值。
- 后续写作必须保持层次感，避免将基础管理痛点、AI 能力不足、安全合规背景、技术实现和落地价值混在同一段中并列堆砌；优先采用“基础问题/进一步问题/行业约束”“能力建设/AI 增强/落地价值”等递进结构。
- 业务痛点应聚焦文档资料分散、纸质/电子附件检索困难、历史资料内容难以沉淀、人工查找效率低、涉密资料不适合外部云端处理等问题。
- PPT 中可引用的业务痛点表达为“三多一少二难”：
  - 文档数量多：日常工作沉淀的制度、通知、方案、报告、清单、附件等资料持续增加。
  - 文档种类多：既有 Word、PDF、图片、表格等不同格式，也有正式文件、过程材料、业务资料等不同类型。
  - 保存方式多：资料可能分散在个人电脑、文件夹、聊天记录、临时目录或不同业务人员手中。
  - 统一管理应用少：缺少统一的文档管理入口，更多依赖个人习惯进行命名、归档和查找。
  - AI 智能辅助手段少：文档内容没有充分结构化和知识化，难以直接利用 AI 进行问答、总结和材料生成。
  - 查找困难：不知道准确文件名时，很难按内容、主题或业务问题定位相关资料。
  - 再利用困难：历史文档中的经验、数据和表述难以快速汇总复用，影响材料撰写、业务总结和日常协同效率。
- 技术亮点应结合前端、后端、数据库、文件处理、内容提取、MCP 服务、权限控制、Docker 本地化部署等现有项目能力。
- 完整说明文档的“系统总体架构与技术组成”中，后端应单独展开：Node.js + Express + TypeScript 后端承担 REST API、JWT 认证、角色权限、文档元数据、附件上传下载、导入导出任务、文件处理状态、内容提取任务调度和统一数据校验等职责。
- 完整说明文档的“系统总体架构与技术组成”应先设置独立“技术栈总览”表格，再按前端应用层、后端服务层、数据与内容处理层、MCP 工具调用层、Skill 与 Agent 辅助层、本地化部署层分别说明作用；AI 增强部分中 MCP 和 Skill/Agent 要分开成段，不混在一句话中。技术栈表中具体模型统一抽象为 LLM，不把 Claude Code 等研发辅助工具写入运行技术栈；具体 AI 工具和模型不再写入完整说明正文，应由提效说明材料单独承接。
- 在第四部分已有技术栈总览表格后，各分层说明不要重复堆技术栈名称，应重点说明模块职责、业务作用和层间配合。
- 完整说明文档的“核心业务流程”应采用“用户动作 -> 系统处理 -> 结果产出”的场景化流程写法，覆盖文档登记与附件归档、内容提取与知识化、常规字段检索、按内容查找与 Smart Extract 片段定位、Dify + MCP 系统内对话式查询、OpenClaw + Skill 辅助分析与报告初稿、资料交接复用与人工审核。
- 安全合规表述应强调本地化部署、隔离测试环境、权限控制、数据访问边界、敏感信息不外传。
- AI 工具使用说明应区分“AI 辅助编程/研发提效”和“系统内 AI 增强能力”，避免夸大尚未落地的功能。
- 提效说明材料若写 AI 辅助开发过程，应突出“人主导需求判断和业务设计，AI 工具辅助规划、文档细化、编码、调试、Skill 封装和 Agent 平台迁移”，不要表述为 AI 全自动完成项目开发；完整说明文档正文不再展开这一过程。
- “核心创新点与落地价值”写作口径：创新点应体现“文档管理 -> 内容提取与片段算法 -> Dify + MCP 系统内嵌智能助手 -> OpenClaw 等 Agent 平台 + Skill 多 Agent 分析与模板化报告生成 -> AI 辅助研发”的递进链条；落地价值应按管理价值、知识价值、业务价值、安全与推广价值分层说明。
- MCP 表述边界：MCP 服务接入定制化 Dify 平台，作为 LDIMS 系统内嵌智能助手的工具调用层，提供文档搜索、文档详情读取、附件内容读取、元数据查询等能力；不要表述为面向 OpenClaw 或其他外部 Agent 平台的通用开放接口。
- MCP 实现细节可用于完整说明文档：MCP 服务基于 `@modelcontextprotocol/sdk`，主要暴露 `searchDocuments`、`get_document_file_content` 两个工具和 `ldims://docs/{document_id}/extracted_content` 资源；向下调用 LDIMS 后端 API，支持参数校验、超时、重试、错误转换、HTML 转义和 Smart Extract 片段返回。开发期 Mock 搜索逻辑已禁用，当前表述应以真实后端 API 调用为准。
- Skill 表述边界：参赛正文中统一称为“Skill”，不在 Skill 前加“SQL”；它面向 OpenClaw 等 Agent 平台和多 Agent 场景，本项目当前基于 OpenClaw 使用，可脱离 LDIMS 前端界面使用，承接 MCP 已有文档检索、内容读取和元数据查询能力，并扩展数据库只读查询、关键词联想、片段提取、AI 摘要和模板化报告生成。
- Smart Extract 表述可更具体：支持 full/smart_extract 内容模式，默认 smart_extract；通过关键词定位、上下文窗口、标点边界延伸、重叠区间合并、命中关键词统计、片段跨度和文档位置评分，返回结构化 snippets 和 matchedContext，用于减少 token 消耗并增强可追溯性。
- 完整说明文档第五部分“核心 AI 创新点与能力设计”的小节顺序应为：文档内容知识化沉淀 -> Smart Extract -> MCP 工具调用层 -> Skill 只读分析与报告生成 -> MCP 与 Skill 分工边界。Smart Extract 需要在 MCP 前面说明，并明确它同时应用于 MCP 和 Skill 两条链路。

## Skill 能力边界

- 当前可见 Skill 目录为 `C:\Users\Administrator\.codex\skills\sql-query`。
- 技能定位：连接 LDIMS MySQL 数据库，结合 SQL 检索和 AI 分析，查询文档及附件内容，支持内容摘要和报告生成。
- 创建/封装表述：参赛材料中统一描述为“将 LDIMS 数据库只读查询、文档内容检索、AI 摘要和报告生成能力封装为可被 OpenClaw 等 Agent 平台调用的 Skill”，突出 AI 辅助研发和能力组件化，不在 Skill 前添加数据库查询类型前缀。
- 核心脚本：
  - `sql_query.py`: 直接执行只读 SQL 查询，输出 Markdown 或 JSON。
  - `analyze_content.py`: 按关键词检索 LDIMS 文档库，支持详细片段输出、文档列表模式、AI 总结模式。
  - `report_writer.py`: 基于模板文档和数据库检索结果生成 Markdown 或 DOCX 报告。
  - `select_sample.py`: 列出、查找和预览报告模板。
- 安全边界：技能内置只读限制，阻止 DROP、DELETE、TRUNCATE、ALTER、CREATE、INSERT、UPDATE、REPLACE、GRANT、REVOKE 等操作；普通 SQL 查询必须以 SELECT/WITH/EXPLAIN/SHOW/DESCRIBE/DESC 开头。
- 检索能力：面向 `documents`、`document_files` 等 LDIMS 数据表，重点使用 `document_files.extracted_content` 做全文内容检索和片段提取。
- 内容分析能力：支持关键词联想扩展、模糊匹配、BM25 重排序、相关片段提取、基于问题的多文档 AI 摘要。
- 报告生成能力：可读取 DOCX/MD/TXT 模板，分析标题格式、段落层级和行文风格，再结合数据库检索内容生成报告；缺失资料应以 `[待补充:xxx]` 标记。
- OpenClaw 等 Agent 平台 + Skill 表达方式：可将 Skill 描述为 LDIMS 在系统界面之外的智能辅助访问方式，本项目当前通过 OpenClaw 调用 Skill，对文档库进行只读查询、内容检索、片段提取、AI 总结和模板化报告生成，实现脱离业务系统界面的资料查询、内容汇总和报告初稿辅助生成，同时保留面向类似 Agent 平台复用的可能。
- 参赛材料中的表述建议：可将该技能描述为“在 LDIMS 数据库和文档内容基础上进行智能检索、摘要分析和规范化报告生成的辅助能力”，突出本地数据、安全只读、从已有文档生成内容，避免表述为绕过权限、无限制自动写库或直接接入生产系统。
